# SDF 소품/문 계획서 (M-D0 ~ M-D3)

`docs/game-framework-plan.md` §6 이연 순서의 다음 항목: **SDF 소품 충돌·문(동적 GI
결정 포함)**. 당시 v1 제약 — "움직이는 오브젝트는 GI/SDF에 안 보이므로 여닫이 문은
GI 잔상이 남는다 → 회피" — 은 글로벌 필드 U2(정적/무버블 2-레이어, `6744e97`)가
해제했다: 문은 **U2 무버 경로의 첫 리지드 콘텐츠 소비자**다. 열리고 닫히는 문이
그 프레임의 거리장에 들어가고, AO/GI/소프트섀도가 따라온다 — 이 트랙의 존재 이유이자
최종 게이트.

기반 현황: `procgen::Tile::Door`(복도가 방 벽을 뚫는 1타일 출입구)는 **이미 감지·
마킹**돼 있고 v1은 열린 바닥으로 렌더한다("문 메시는 계획이 이연" — 그 이연이 여기).
소품 파이프라인(프로시저럴 rig → .glb → 레벨 엔티티, 횃불/플라스크 선례)과 U2
엔티티-키 sync(레벨 로드 시 존재하는 엔티티는 자동 추적)도 준비돼 있다.

## 1. 마일스톤

- **M-D0 — 문 소품 + 배치**: `rigs::door()` 프로시저럴 메시(패널+틀, **힌지 모서리가
  로컬 원점** — 루트 Y-회전이 곧 스윙), `level.rs`가 모든 `Tile::Door` 타일에
  `door_<i>` 엔티티 배치(방향 = 벽 이웃 축에서 유도, 스윙 방향 = 방 안쪽으로 결정적).
  게이트: 유닛(모든 출입구에 정확히 1문, 시드 결정적 방향/개수) + 닫힌 문 캡처.
- **M-D1 — 문 시뮬 + 충돌**: `DoorWorld` 상태기(Closed→Opening→Open→Closing,
  FIXED_DT 스텝 스윙 ~0.35 s), **근접 자동 개방**(플레이어·그런트 공용 — AI가 문에
  막혀 멈추는 문제를 원천 회피; A* 는 문 타일을 계속 통행 가능으로 계획), 닫힌 문 =
  해당 타일 동적 차단(문-인지 충돌 래퍼; 그리드 충돌 v1 위 오버레이 — "SDF 소품 충돌"
  의 v1 형태, 캡슐-vs-SDF 일반 쿼리는 필요 소품이 생길 때). 문 개폐 SFX 2종
  (프로시저럴 크리크/썸 — 뱅크 해시 재기준선, 의도된 변경으로 기록). 게이트: 유닛
  (닫힘=차단·접근=개방·통과·재폐쇄, 시뮬 결정성 불변).
- **M-D2 — 동적 GI/그림자 실증(트랙의 존재 증명)**: 같은 카메라에서 문 닫힘/열림
  캡처 쌍 — 출입구의 AO/GI 차이 + `DIAG_GDF_GLOBAL` 로그에 문 승격(무버블 +1)과
  소풋프린트 merge 확인, VSM 페이지 무효화 동작 확인. **한계 기록**: HWRT 경로의
  콘텐츠 TLAS는 로드 1회 빌드라 문이 스테일 — Apple 티어(SWRT)는 무관, Windows
  HWRT 티어의 TLAS 리핏은 DX≡VK 원장에 등록(별도 증분).
- **M-D3 — 배터리 + 랜딩**: 골든(gallery/gdf_ao/OFF-경로) 불변, 보행 캡처 델타,
  clippy/fmt/테스트, 문서/메모리, 커밋·푸시.

## 2. 설계 결정

- **자동 개방(상호작용 키 없음, v1)**: 탑다운 액션의 문은 흐름 장치지 퍼즐이 아니다.
  캐릭터 원이 ~1.6 m 안이면 열리고, 비면 ~1 s 후 닫힌다. Interact 키/잠긴 문은 열쇠
  콘텐츠가 생길 때(액션·바인딩 시임은 그때 추가).
- **충돌 = 타일 오버레이**: 문은 정확히 1 출입구 타일을 점유하므로 "닫힘 = 그 타일
  일시 솔리드"가 그리드 충돌 v1과 정합. 부분 개방 중에도 차단(스윙 중 끼임 방지,
  0.35 s라 체감 없음).
- **라이선스**: 신규 자산/의존성 없음(메시·SFX 전부 프로시저럴).

## 3. 리스크

- **뱅크 해시 게이트 이동**: SFX 추가 = 의도된 해시 변경 — 재기준선을 커밋 메시지에
  명시(오디오 트랙의 게이트 규약).
- **문 스윙과 U2 병합 비용**: 문 1장 = 파트 1개(리그 63개 대비 무시량), 스윙 프레임
  ~0.35 s 동안만 merge — 실측 로그로 확인.
- **그런트 경로**: 자동 개방이 지연을 만들지만 차단은 안 함 — A* 불변이 정답(문에서
  대기하는 브레인 상태 불필요).
