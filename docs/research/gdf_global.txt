TOPIC: reference engine Global Distance Field — camera-centered sparse page clipmaps, GPU composition, dynamic updates (source: local UnrealEngine-1 checkout)

Architecture (GlobalDistanceField.cpp):
- Clipmaps: NumClipmaps=4 (cvar :82), camera-centered, exponent-spaced coverage (ClipmapDistanceExponent=2, :154). Clipmap resolution 128^3 (GAOGlobalDFResolution=128, :162; Lumen scales by view distance :466-481). Each level snaps to a page grid; ScrollOffset modulo clipmap size so "the contents don't have to be moved as the camera moves around, only updated in slabs" (:1319-1322) — toroidal addressing, consumed with a WRAP trilinear sampler on the page atlas (:387 TStaticSamplerState<SF_Trilinear, AM_Wrap×3>).
- SPARSE pages: the clipmap virtual volume maps through a page table to a shared page ATLAS texture (128×128×N pages, :453-454, sized :519-540). Only pages near surfaces get physical backing; a free list recycles them. This bounds memory by SURFACE AREA, not world volume.
- Dual cache layers: r.AOGlobalDistanceFieldCacheMostlyStaticSeparately=1 (:106-109) doubles the page budget (:525) — a MOSTLY-STATIC layer cached across frames and a MOVABLE layer recomposited per frame, merged for sampling. The exact static/dynamic split our VSM V3 landed for shadow pages.
- Update flow per frame: view moves → per-level origin snap + scroll; modified primitives report bounds (debug hooks :320-333) → dirty page regions; GPU pipeline: CullObjectsToClipmapCS (:1466-1505) → CullObjectsToGridCS (:1581-1617, a per-update-region object grid) → CompositeObjectsIntoObjectGridPagesCS / CompositeObjectsIntoPagesCS (:1640-1684, GlobalDistanceFieldCompositeObjects.usf) — per-voxel min over culled object SDFs, written into the page atlas. Heightfields composite separately.
- Far stepping: a coarse MIP texture per clipmap (GetClipmapMipResolution :483-485, mip factor 4 → 32^3), CLAMP-sampled (:388), used to take large steps far from surfaces before refining in the page atlas.
- Object stage stays world-anchored: mesh SDFs live in their own atlas; the global field is a derived cache. Lumen traces detail mesh SDFs near the ray start and the global field beyond.

Adaptation notes for DreamCoast (per-mesh atlas + instance table already on GPU; VSM page machinery precedent in vsm.rs):
1. Our per-mesh direct-sample path already implements the OBJECT stage (atlas + cell grid + detail-replace). The reference's global field replaces our dense 48^3 scene volume: N=4 camera-centered levels, page-sparse, wrap-sampled, GPU-composited from the SAME instance table the direct path uses. Consumers keep entering through ms_geo/cm_geo — the dense fallback swaps for the global-field sampler behind one seam.
2. Reuse the VSM V1-V3 patterns wholesale: page table entry encoding, free-list rebuild via compact (the decrement-undo phantom-pop lesson), double-footprint invalidation for movers, static/movable layer split with merge-on-write.
3. GPU composite kernel = compose.rs's nearest-surface-wins union, per page voxel, over the per-clipmap culled instance list (broad-phase AABB vs page bounds). The CPU compose stays as the cook-time/gallery path.
4. Albedo: same page geometry, composited from the per-mesh albedo atlas (F5); constant fallback where absent.
5. Dynamic contract (the standing directive): instance transforms upload per frame; moved instances mark old+new page footprints dirty; movable layer recomposites dirty pages every frame; static layer only on scroll/level invalidation. Characters enter later as capsule proxies (separate track).
