# Phase 프롬프트 — TAAU 이동 블러(모션 샤프니스) 회복

> 사용자 보고(2026-07-25): Med 승격(rs 0.6667+TAAU) 후 "이동시 TAA 특유의 블러가
> 너무 심함". 벨로시티 버퍼 구현 포함 어떤 수단이든 이동 중 선명도를 회복할 것.

## 진단 (코드 판독 완료, taau.slang)

1. **히스토리 페치가 빌리니어** (`fetch_history_bilinear`, taau.slang:97-105) — 서브픽셀
   이동마다 빌리니어 리샘플이 반복돼 누적 소프트닝(이동 블러의 고전 주범). 히스토리는
   텍스처가 아니라 **스토리지 버퍼**(수동 빌리니어 + world-pos 디스오클루전 가중)라
   업계 표준 처방(Catmull-Rom 5-bilinear 트릭)을 그대로 못 쓰고 수동 구현 필요.
2. **Lottes 루마-가중 피드백**: luma 안정 픽셀에서 히스토리 편향↑ = 이동 중 스미어 가중.
3. **`P_TAAU_CLAMP_EXPAND` 기본 2.0**: 고대비 정적 에지의 재클립 방지용 박스 확장이
   이동 중엔 유령/블러를 연장.
4. **`taau_antiflicker`(luma 댐핑, Med 기본 ON)**: 밝은 신규 샘플의 블렌드 가중치를
   낮춤 — 정지 셔머엔 결정적이나 이동 중엔 응답성(선명도)을 깎음.
5. 벨로시티 버퍼는 **존재**(velocity.rs, taau.record가 `velocity_target` 수신) — 카메라
   재투영은 행렬 기반으로 정확. 문제는 재투영 오류가 아니라 **리샘플/블렌드 정책**.

## 처방 후보 (우선순위)

- **A. Catmull-Rom 히스토리 리샘플**: 수동 buffer-fetch CR(3×3 가중, 코너 절약 9→5탭
  변형은 버퍼라 불가 — 9탭 or 12탭). 업계 표준 최대 효과. 비용: 히스토리 로드 4→9탭
  (fp16-packed 경로면 트래픽 절반). PROFILE_GPU로 taau 패스 비용 확인(현 0.47ms).
- **B. 속도-게이트 정책**: |velocity| ∝ ① 블렌드 알파 상향(신규 샘플 가중↑) ② 안티플리커
  댐핑 완화 ③ clamp_expand 축소. 정지=현행(셔머 게이트 유지), 이동=응답성 우선.
  F6O do-not-retry(TAAU 내부 이웃-클램프 변형 금지)와 충돌하지 않음 — 클램프 형태가
  아니라 가중치 정책.
- **C. 포스트-업스케일 샤픈 강도**(main.rs:8737 존재) 재튜닝 — 보조 수단.

## 게이트

- **신설 모션-샤프니스 지표**: 돌리 CAPTURE_SEQ 중간 프레임의 그래디언트 에너지
  (엣지 필터 평균) vs 정지 프레임 비율 — tools/seq-stability.py에 `--sharpness` 추가.
  수정 전 기준선 측정 → 래칫.
- 기존 셔머 래칫 **유지 필수**: 돌리 door-ROI ≤ 2.2, bright-std ≤ 60 (B가 이동 중
  안티플리커를 완화하므로 이 게이트가 반대 방향 회귀를 잡는다).
- 갤러리 앵커 불변(native라 TAAU 비활성 — 구조적으로 안전), DX≡VK, PT 게이트 불변
  (RENDER_SCALE=1).
