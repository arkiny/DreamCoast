# GDF 카메라 추종 클립맵 계획서 (G0 ~ G3) — **대체됨**

> **SUPERSEDED (2026-08-04)**: 승인 후 착수 단계에서 전제 결함 확인 — 콘텐츠의 GDF
> 소비는 퍼-메시 직접 샘플 경로(`P11_DIRECT_SDF` 기본 ON, `count==0`)라 본 계획의
> 파이너 밀집 레벨을 마치하지 않는다. 후속: `docs/gdf-scale-follow-plan.md`(코어스
> 필드/알베도의 카메라-추종 토로이달 창 — 직접 경로가 실제 의존하는 자원). 아래
> 원문은 밀집 폴백 티어(P11_DIRECT_SDF=0)에 한해 유효한 설계 기록으로 보존.

`crates/../clipmap.rs`가 예비해 둔 업그레이드("the seam the future camera-following"):
현행 GDF 클립맵은 **로드 시점 카메라**에 레벨을 앵커해 정적으로 굽는다. 이 트랙은
레벨을 **런타임 카메라에 추종**시키고, 레퍼런스 엔진 Global Distance Field의 계약
(GlobalDistanceField.cpp:1319 — *"contents don't have to be moved as the camera moves,
only updated in slabs"*: 스크롤 오프셋 모듈로 + 슬랩 부분 갱신 = 토로이달 어드레싱)을
우리 자료구조에 맞게 들여온다.

동기: 현행 방식은 씬 전체가 정적 볼륨 예산 안에 들어갈 때만 성립한다(던전 80×80 m는
되지만 더 큰 층/야외는 안 됨). 추종 클립맵은 월드 크기와 무관하게 **카메라 근방 복셀
밀도를 일정**하게 유지한다 — GI 파인 볼륨(토로이달 재중심, `0360c08`)과 같은 정책을
GDF에 적용하는 것이며, GDF는 소비자 다수가 수동 샘플이라 이번엔 **주소-감기(진짜
토로이달)**가 맞는 선택이다(하드웨어 필터링 심 문제는 REPEAT 샘플러가 흡수).

## 1. 목표 / 비목표

**목표**
- 파이너 클립맵 레벨(코어스 제외 전부)이 카메라를 추종: 페이지-스냅 재중심,
  토로이달 UV 스크롤, 새로 노출된 슬랩만 재합성.
- 정적 카메라 = 재중심 없음 = **골든/PT 게이트 바이트 불변**(GI 파인과 동일 불변식).
- 소비자(cm_geo_march/inside, cm_albedo — AO/GI/반사/스카이비스/캐시 재조명) 무접촉
  또는 clipmap.slang 한 곳의 어드레싱 변경으로 국소화(단일 소스 원칙).

**비목표 (순서만 기록)**
- 코어스(최외곽) 레벨의 추종(씬 AABB 커버 유지 — 폴백 레벨).
- GPU 합성 커널(G2에서 비용 실측 후 별도 증분 — v1은 CPU 슬랩 합성+부분 업로드).
- 동적 오브젝트의 GDF 편입(별도 트랙 — SDF 소품 충돌·문 트랙과 연동).

## 2. 설계

- **재중심**: 레벨별 데드존(반경의 1/4, GI 파인과 동일 철학) 이탈 시 페이지 격자
  (슬랩 = 볼륨 1행, 48³ 기준 48×48×1 복셀)로 스냅한 정수 페이지 델타를 arm.
  다음 프레임 pre-graph에서 적용(GI 토로이달과 같은 2-페이즈 — `0360c08` 패턴).
- **토로이달 어드레싱**: 레벨 볼륨은 콘텐츠 제자리, 레벨 desc에 `uv_scroll`(복셀
  단위 정수, 모듈로 dims) 추가. clipmap.slang의 레벨 샘플 함수 한 곳에서
  `uv = frac(local + scroll)`; 샘플러는 GDF 클립맵 레벨 한정 REPEAT(신규 샘플러
  슬롯 — 기존 클램프 샘플러 소비자는 무접촉). 레벨 경계 처리(컨테인먼트/페이드)는
  현행 로직 그대로 — 어드레싱만 바뀐다.
- **슬랩 재합성**: 스크롤로 새로 노출된 평면 슬랩들(축당 |delta| 행)을
  `compose_sdf_level`의 슬랩-스코프 변형(CPU, 기존 코드 재사용)으로 합성해
  **볼륨 부분 업로드**(RHI에 write_region 시임 필요 — 3백엔드). 알베도 3채널 동일.
  프레임 예산: 축당 최대 2행/프레임(초과분은 다음 프레임 — 재중심 자체가 데드존
  간격이라 밀릴 일이 드묾), 나머지는 이전 콘텐츠 유지(코어스 폴백이 이미 있으므로
  일시적 스테일은 근사 오차, 아티팩트 아님).
- **결정성**: 재중심은 카메라 이동에서만; CAPTURE_SEQ 보행 캡처는 결정적 스텝이라
  재현 가능(시퀀스 검증 레시피 재사용).

## 3. 마일스톤

- **G0 — 시임/계측**: 레벨 desc에 uv_scroll(항상 0) 배선 + REPEAT 샘플러 경로 추가,
  `P11_GDF_FOLLOW=0` 기본 OFF. 게이트: scroll=0에서 골든 배터리 byte-PASS(어드레싱
  개조의 무해성 증명), 레벨 쿡/합성 비용 실측 로그.
- **G1 — 재중심+슬랩 갱신**: 데드존→arm→적용(2-페이즈), CPU 슬랩 합성+write_region,
  던전 보행 시퀀스에서 프레임 델타 프로파일(재중심 프레임 ≈ 인접 프레임 — GI 때와
  동일 판정법). `P11_GDF_FOLLOW=1`로 온.
- **G2 — 예산/폴리시**: 슬랩 예산 상한 실측(프레임 스파이크 없음), 층 전환/핫스왑
  전체 무효화 경로, DIAG 카운터(재합성 슬랩/프레임). 기본 ON 판정(콘텐츠 씬).
- **G3 — 검증/편입**: 골든+PT 게이트(정적 불변), 던전/sponza 플레이, 메모리 원장,
  DX≡VK 배치 등록. quality.rs 티어 노브(레벨 수/target_voxel)는 여기서.

## 4. 리스크

- **부분 업로드 RHI 시임**: 3백엔드 write_region — Metal(replaceRegion)/VK(buffer
  copy region)/DX12(WriteToSubresource 또는 staging copy). 이번 트랙의 유일한 RHI
  변경; Metal 먼저, DX≡VK는 배치.
- **슬랩 합성 CPU 비용**: 48×48×1 복셀 × 인스턴스 그리드 조회 — 로드 시 전체 레벨
  합성이 밀리초대인 것으로 보아 슬랩은 마이크로초대 예상이지만 G0에서 실측이 게이트.
- **레벨 경계 페이드와 스크롤의 상호작용**: 경계 로직이 월드-AABB 기반이므로 레벨
  AABB 갱신과 스크롤이 원자적으로 같은 프레임에 적용돼야 함(2-페이즈가 보장).
- **GI 볼륨과의 결합**: gv 트레이스가 클립맵을 읽음 — 재합성 패스를 소비자보다
  그래프 선행 배치(gi_shift와 동일 패턴).
