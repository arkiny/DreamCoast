# 비동기 레벨 핫스왑 계획서 (H0 ~ H3)

층 이동(계단 하강) 시 레벨 핫스왑이 렌더 스레드에서 동기로 돌아 **~300 ms 프레임
히치**가 발생한다(실측: DIAG_FRAME_CSV, 층 전환 프레임 277–297 ms ×2 + 후속
87–105 ms). 히치의 구성은 로그 기준: glTF 로드/파싱 → per-mesh SDF 쿡(캐시 히트
포함 — 읽기·디코드도 비용) → 씬 SDF/알베도 컴포즈 → 서피스 캐시 재구축 →
BLAS/TLAS 재빌드 → vgeo 클러스터 DAG 쿡 → GDF 글로벌 설치. 목표는 **엔진 일반
수준의 비동기 씬 설치 파이프라인**이다(게임 전용 패치 금지 — 스트리밍/월드 전환이
있는 모든 콘텐츠가 소비자).

## 0. 구조 결정

- **스레드 계약**: rhi-metal의 디바이스 공유 상태는 `Rc<DeviceShared>`(비-Send).
  따라서 GPU 리소스 생성/업로드는 렌더 스레드 소유로 유지한다. 오프스레드로
  옮기는 것은 **CPU 산출물 생산 전부**: 파일 IO, glTF 파싱, SDF 쿡(이미
  `dreamcoast_jobs` 병렬 — 단 현재는 완료를 렌더 스레드가 **블로킹 대기**),
  컴포즈 베이크, vgeo DAG 쿡, BLAS 입력 준비.
- **파이프라인 형태**: `PendingScene`(CPU 산출물 묶음)을 잡 시스템에서 조립 →
  렌더 스레드는 매 프레임 `poll()` — 준비 완료 프레임에 ①GPU 업로드(버퍼/볼륨
  생성 + init 카피) ②원자적 포인터 스왑 ③구 씬 리타이어(FIF 무덤 — 스트리밍
  스왑·샘플드 슬롯 회수와 같은 규율)를 수행한다.
- **업로드 비용 상한**: 업로드+스왑 프레임의 실측이 60 ms를 넘으면 업로드를
  프레임당 예산(기본 8 ms)으로 분할하는 H3로 확장한다. 층 전환 중에는 구 씬이
  계속 렌더되므로 분할은 안전하다.
- **결정성**: 헤드리스/캡처 모드는 **동기 경로 유지**(기존 코드 그대로) — 골든
  byte-PASS 불변의 구조적 보장. 비동기 경로는 윈도우드 인터랙티브 전용이며
  `ASYNC_SWAP=0` 시임으로 끌 수 있다(모든 비자명 레버의 규칙).

## 1. 마일스톤

- **H0 — 경로 분해**: `static_scene.rs` 설치 체인을 "CPU 산출물 조립"과 "GPU
  설치"의 두 함수로 분리(순수 리팩터, 동작 불변). 게이트: gallery/sponza 골든
  byte-PASS + 층 전환 실측 동일.
- **H1 — 오프스레드 조립**: CPU 조립을 `dreamcoast_jobs` 태스크로 이동,
  `PendingScene` + `poll()` 시임 추가. 던전의 층 전환을 이 경로로 전환(계단
  진입 시 요청 → 준비 완료 프레임에 스왑; 전환 연출은 게임 소관, 엔진은 API만).
  게이트: DIAG_FRAME_CSV로 층 전환 구간 >60 ms 프레임 0개, 골든 불변.
- **H2 — 구 씬 리타이어 규율**: 스왑 후 구 씬의 GPU 리소스를 FIF+1 프레임
  무덤에서 해제(바인드리스 슬롯 회수는 기존 Drop 프리 리스트 경유). 게이트:
  DIAG_SLOTS로 슬롯 순증 0(전환 10회 반복 프로브), 크래시/검증 레이어 무경고.
- **H3 (조건부) — 업로드 분할**: H1 실측이 60 ms를 넘길 때만. 업로드 큐 +
  프레임 예산. 게이트: 동일 프로브 >60 ms 0개.

## 2. 리스크

- **잡 시스템 재진입**: per-mesh SDF 쿡이 이미 워커를 쓰므로, 조립 태스크가
  내부에서 다시 fan-out할 때 워커 고갈로 교착하지 않는지 확인(잡 시스템의 중첩
  스폰 정책 검토가 H1 선행 항목).
- **ECS/게임 상태와의 핸드셰이크**: 스왑 프레임에 시뮬이 구 층 엔티티를 만지지
  않도록, 게임 쪽 요청-완료 2단계 API(요청 시 시뮬은 전환 상태로)로 명확화.
- **cache/generated 경합**: 조립 태스크의 쿡 캐시 쓰기와 동시 실행 안전성 —
  파일 캐시는 per-mesh 콘텐츠 해시 키라 충돌 없음, 동일 키 중복 쓰기는 멱등.

## 3. 게이트 요약

golden byte-PASS(헤드리스 동기 경로 불변) · clippy -D warnings · 층 전환 10회
반복 윈도우드 프로브(DIAG_FRAME_CSV >60 ms 프레임 0, DIAG_SLOTS 순증 0) ·
무거운 작업 1개씩(팬리스 M3 Air).

## 4. H0 착수 정찰 (2026-08-11, 구현 진입점)

- `lib.rs::load_level`(4312) 체인: RHI 워커 드레인 → wait_idle → `level::load`(IO/파스)
  → `level::build_level`(메시/머티리얼/텍스처 — GPU 업로드 혼재) → transform 전파
  → `rebuild_static_scene`(4406) → 워커 재스폰 지연 처리(기존 주석의 FIF 스크래치
  주의사항 참조 — 비동기화 시에도 동일 계약 유지 필요).
- `static_scene.rs::build_gdf_scene`(75~842)의 페이즈 구조:
  - **A(디바이스-프리 확인됨)**: specs 수집(dedup, 레지스트리를 소유 바이트로 인코딩
    — "borrows no registry" 주석, 이미 Send-호환) + parallel_cook per-mesh SDF/알베도
    베이크(172~370). → `bake_mesh_fields()` 순수 함수로 추출이 H0 1호 커밋.
  - **B(혼재)**: 컴포즈/씬 볼륨/아틀라스/글로벌 필드/서피스 캐시 — device 터치포인트
    ~10곳(434 set_clip_levels, 539/553/570 볼륨 생성, 750 카드 캡처 등). CPU 산출물
    구조체로 감아 업로드 함수와 분리하는 것이 H0 2호.
- vgeo DAG 쿡·BLAS/TLAS는 별도 모듈(vgeo.rs/rt.rs) — H1에서 같은 PendingScene에 합류.
- 주의: 스왑 시 sun/카메라/level_lighting 등 앱 상태 갱신은 스왑 프레임에 원자 적용.
